## 14. M4 구축 기록 (2026-11-11)

> 이 기록 뒤에 바뀐 것: 분기(FR-14)는 체크포인트에서 이어 가게 되었다가 분기 양식이 없어지고 구간 실험이 그 일을 한다([15 §15.7](./15-m4-improvements.md), [16](./16-lab-runs-and-experiment-sets.md)). 처리 방식은 모자이크 하나다. 출력 검증은 10~11행이다. 위치 메타데이터는 판단 대상이 되었다(§15.5). 검토 미리보기의 영역은 서버가 계산한다(§15.4). 비용 상한은 $1.00이다. 1.0 코드와 옛 테스트(`backend/tests/legacy`)는 2026-11-12에 저장소에서 지웠다([16 §16.10](./16-lab-runs-and-experiment-sets.md)).

M4의 목표는 세로 슬라이스다: 영상 하나가 업로드에서 출력 영상과 보고서까지 실제 모델과 실제 렌더로 끝까지 간다. 사용자 지시에 따라 **어떤 코퍼스를 넣을지와 판결문의 어느 부분을 저장할지는 M4에서 정하지 않았다**(M4-1). 법률 검색은 M3에서 받아 둔 12건의 색인을 그대로 쓰며, 코퍼스가 바뀌어도 코드가 바뀌지 않게 만들었다.

### 14.2 실행

```bash
uv sync --group models                      # 로컬 모델 의존성
uv run privframe-case make-sample           # 합성 예시 영상 → data/samples/sample.mp4 (없으면 실험실 데모 실행 불가)
uv run uvicorn privframe.service.app:app    # 백엔드 http://127.0.0.1:8000 (이 컴퓨터에서만 접속. 개발 중 자동 재시작은 uv run fastapi dev)
cd frontend && PRIVFRAME_API=proxy npm run dev   # 화면 http://localhost:5180 → 실제 백엔드

uv run privframe-case run <영상> --memo "…"       # 화면 없이 한 건 처리 (질문은 터미널에서 답함)
uv run privframe-case run <영상> --auto --answer purpose.publication_scope=public
PRIVFRAME_FIXTURE=1 uv run uvicorn privframe.service.app:app   # 고정 응답으로 실행: 키 · 네트워크 · 모델 불필요
uv run --group models pytest                      # 새 테스트 (옛 1.0 테스트는 backend/tests/legacy 를 따로 실행)
```

- 케이스는 `data/cases/<케이스 ID>/`에 저장된다: 원본, 프록시, 지각 산출물, `understanding.json`, `regions.json`, 출력 영상, `report.json` · `report.html`, 이벤트 로그(`events.jsonl`), 화면용 스냅샷(`case.json`). 그래프 상태는 `data/cases/checkpoints.sqlite`.
- 예시 영상은 합성이다. 얼굴은 공개 저작물인 NASA 시험 초상(scikit-image `astronaut`) 하나뿐이고 이름 · 번호판은 지어낸 것이다. 실험실의 데모 실행과 "예시 영상"이 이 파일을 쓴다.

### 14.4 그래프와 에이전트

- **그래프**는 설계 D4 그대로다. `perceive`는 서브그래프(검출 뒤 인물 묶음 → 인물 속성, OCR, 장면 설명이 병렬)이고, 사람을 기다리는 곳은 `interrupt()`다: 대상 확인, 질문(에이전트의 `ask_user` 도구 안), 계획 검토, 감사 확인. 검토에서 사실을 고치거나 늦게 답하면 `await_review → legal_analyst`로 돌아가 다시 분석하고 계획을 다시 세운다.
- **Legal Analyst**는 `create_agent`로 만들고, 믿어야 하는 것은 모델 밖의 코드가 맡는다.
  - 도구가 돌려준 근거만 인용할 수 있다. 인용은 근거 ID(`pipa#제17조`)로 하고 표기는 코퍼스에서 꺼낸다 ([ADR-0010](../adr/0010-cite-by-evidence-id.md)).
  - 미들웨어가 예산을 지킨다: 도구 호출, 검색 횟수, 같은 질의 반복, 질문 라운드, 케이스 비용 상한.
  - `finalize`가 제출하면 검증기가 본다: 없는 근거 ID, 근거 없는 단정, 참고(3) 자료만으로 적용 단정, 요건의 출처, 대상과 범위의 짝. 문제는 사유와 함께 모델에 되돌리고(재시도 상한까지), 끝내 못 고치면 검증할 수 없는 부분을 빼고 미해결로 남긴다.
  - 커버리지 점검은 관찰과 맞닿는 참고 패턴 가운데 분석이 다루지 않은 것을 질문으로 한 번 되돌린다. 결정을 강제하지 않는다.
  - 질문 게이트는 이미 아는 사실, 이미 물은 것, 답에 따라 처리가 달라지지 않는 질문, 상한을 넘는 질문을 뺀다. 뺀 질문은 이유와 함께 화면에 보인다.
  - 분석이 예산 안에 끝나지 않으면 개인을 알아볼 수 있는 모든 대상을 가리는 보수적 요건으로 넘어간다(불확실로 표시).
- **Planner**는 모델이 제안하고 코드가 검사한다(요건마다 대상 · 범위 · 구간이 덮였는지). 상한까지 통과하지 못하면 요건을 그대로 따르는 규칙 기반 계획을 쓴다. 요건이 없는 대상은 유지 결정으로 목록에 남는다.
- **출력 전 사람 승인**은 항상 거친다. 감사(요건 대조)는 검토에서 바뀐 계획이 요건을 깨면 발견으로 돌려주고, 적용하거나 사유를 적어 위험을 수용한다.

### 14.5 서비스

- 케이스 하나가 LangGraph 스레드 하나다. 실행은 서비스 프로세스의 작업 스레드에서 돌고(동시에 2건), 사람을 기다릴 때는 스레드가 끝나며 답이 오면 `Command(resume=…)`로 새 스레드가 이어 간다. Celery는 쓰지 않았다(서비스 분리는 M6).
- 그래프 상태는 SQLite 체크포인트, 화면이 읽는 스냅샷과 이벤트 로그는 파일이다. 서버를 다시 켜도 기다리던 케이스는 그대로 이어지고, 실행 중이던 케이스는 **멈춤**으로 표시되어 "계속"으로 마지막 체크포인트에서 이어 간다.
- 비용이 상한을 넘으면 다음 모델 호출 전에 멈춘다. 상한을 올려야 계속할 수 있다. 실제로 분석 도중에 멈춘 케이스를 다른 프로세스에서 이어 끝냈다(§14.7).
- 실험실 이벤트는 실제 스트림에서 만든다(`core/events.py`). 엣지는 그려진 토폴로지의 엣지 ID로 보낸다. 인용 검증기는 미들웨어 안에서 돌지만 토폴로지에서는 `legal_analyst/validate` 노드로 보인다.
- 질문(`ask_user`)이 다른 도구와 같은 턴에 호출되면, 재개할 때 LangGraph가 그 턴의 다른 도구도 다시 실행한다. 도구 결과를 호출 ID로 보관해 검색이나 시각 점검을 두 번 하지 않게 했고, 다시 보고되는 이벤트는 한 번만 내보낸다.
- 실험실의 프로필 검사에는 카탈로그 규칙에 더해 **이 백엔드가 아직 실행하지 못하는 부품**이 표시된다(오류: 실행하면 멈춤 / 주의: 그 단계 없이 진행 / 정보: M5에서 호출).

화면은 같은 코드로 모의 백엔드와 실제 백엔드에 붙는다. 실제 백엔드에서는 예시 일러스트 대신 프록시 영상 위에 계획의 가림을 캔버스로 미리 보여 주고(렌더러와 같은 상자 · 수준 규칙, `frontend/src/service/media/geometry.ts`), 결과 화면은 실제 출력 파일을 재생한다. 백엔드는 `frontend/dist`가 있으면 화면도 함께 내보내므로 `npm run build` 뒤에는 `http://127.0.0.1:8000`만 열어도 된다.

계약에 더한 것 (화면 계약 `contract.ts`에 반영):

| 추가 | 내용 |
|---|---|
| `GET /api/config` | `backend: "real"`, 예시 영상 유무, 키 유무 |
| `POST /api/cases` | 실제 백엔드는 multipart(`file`, `memo`, `mode`, `sample`) |
| `CaseDetail.media` | `proxy`(H.264 프록시), `frame?t=`(정지 화면), `geometry`(트랙), 완료 뒤 `output`, `reportHtml` |
| 상태 `PAUSED` · `pauseReason` | `budget` · `user` · `restart`. `POST …/pause`, `POST …/resume {costCapUsd?}` |
| `GET …/report.html` | 인쇄용 보고서 |

### 14.6 M4에서 측정으로 정한 것

> 2026-11-11 보완([15-m4-improvements.md](./15-m4-improvements.md)): 흐림과 단색 가림은 삭제되어 아래 표의 "흐림 수준" 행은 더 쓰이지 않는다. 모자이크 블록 수(짧은 변 6개, 글자 · 번호판 2.5배)와 재식별 기준(0.50)은 그대로이고, 출력 검증은 전체 프레임 검사가 더해졌다. 비용 상한은 $1.00으로 바뀌었다.

| 가정 | 설계의 값 | 측정 | 정한 값 |
|---|---|---|---|
| **U9** 처리 영역 밖 화질 기준 | PSNR-Y ≥ 45 dB · SSIM ≥ 0.99 | 팀 영상(720p) libx264 CRF 16의 프레임 최저값은 41 dB · 0.985이고 가림이 없어도 같다(인코더 손실). 45 dB는 CRF 10에서 나오며 파일이 원본의 3~5배가 된다 | **≥ 38 dB · ≥ 0.97.** 이 검사는 가림 밖의 손상(엉뚱한 프레임, 색 변화, 새는 마스크)을 잡는 것이고 그런 손상은 30 dB 아래로 떨어진다 |
| **U10** 고정 수준이 재검출 0을 만든다 | 흐림 σ = 짧은 변의 0.18, 재검출 0 | 흐린 얼굴은 대부분 여전히 "얼굴 모양"으로 검출된다(0.18: 27/30, 0.45에서도 일부, 단색 가림만 0). 검출은 식별이 아니다 | 기준을 **재식별**로 바꿨다: 출력의 얼굴이 원본 얼굴과 얼굴 특징으로 대조되는지(유사도 ≥ 0.50), 글자가 다시 읽히는지(일치 ≥ 0.5) |
| 흐림 수준 | σ = 0.18 × 짧은 변 | 0.18에서 30개 중 1개가 원본과 0.35로 닮았다. 팀 영상 289개 얼굴에서 σ 0.30~0.60, 모자이크 4~6블록 모두 최대 0.31~0.37에 머문다(머리 모양 · 피부색이 만드는 바닥값). 같은 사람의 가리지 않은 얼굴은 0.82~0.99 | **σ = 0.45 × 짧은 변.** 얼굴 모양으로 다시 검출되는 수가 줄어든다(0.30: 169 → 0.45: 96) |
| 글자 · 번호판 수준 | 얼굴과 같음 | 글자 한 줄은 얼굴을 가리는 수준에서도 읽힐 수 있다 | **얼굴의 2.5배**로 거칠게 (흐림 폭, 모자이크 블록) |
| 분석 모델 비용 | 프롬프트 캐시 85% 가정 | 캐시 표시 없이는 6턴에 입력 12만 토큰이 전액 과금되어 분석만 $0.32 | 시스템 프롬프트와 마지막 메시지에 캐시 지점을 둔다(Claude). 같은 영상에서 $0.21 |
| 엄격한 JSON 스키마 | `with_structured_output(strict=True)` | OpenAI 쪽은 모든 객체에 `additionalProperties: false`가 없으면 400을 낸다 | 스키마를 닫아서 직접 보낸다 |

재식별 기준 0.50은 인물 묶음 단계가 두 트랙을 같은 사람으로 묶는 값이다. SFace의 자체 기준(0.363)이나 0.30을 쓰면 바닥값(0.31~0.37)에 걸려 제대로 가린 영상이 무작위로 실패한다. 검증 행에 최대 유사도를 함께 적는다(예: "얼굴 대조 최대 유사도 0.34 (기준 0.50 미만)").

### 14.8 알려진 한계

- **판례 오용이 실제 실행에서 다시 나왔다.** 끝까지 간 실제 실행 세 번 모두 명찰 가림 요건의 근거로 `대법원 2020다253423 5쪽`을 인용했다. 그 쪽에 "얼굴을 가려도 … 알 수 있었다"는 문장이 있기 때문인데, 이 판결은 파기환송이고 그 문장은 반대 방향의 이유로 쓰였다(§12 A). 인용 검증기는 "검색한 근거인가"만 보므로 통과한다. 주문을 청크에 붙일지, 열람 의무와 인용 충실성 검사를 둘지는 코퍼스 결정(M4-1)에 속해 손대지 않았다. **M4-1에서 가장 먼저 정해야 할 항목이다.**
- 시행일 검사는 없다. 지금 코퍼스는 문서마다 현행본 하나뿐이다.
- 번호판 검출기는 실제 번호판 영상으로 확인하지 못했다. 밝은 사각형 위의 어두운 글자(명찰, 표지판)를 번호판으로 잡은 경우가 있었다. 글자는 OCR이 따로 읽어 대상이 된다.
- 글자는 1초마다 읽고 그 사이는 보간한다. 카메라나 사람이 빨리 움직이면 가림 상자가 글자를 조금 늦게 따라갈 수 있고, 출력 검증의 글자 재인식은 상자 안만 읽어 이 어긋남을 잡지 못한다.
- 뒤돌아선 사람처럼 얼굴이 없는 전신 트랙끼리는 묶지 않는다. 낮은 점수로 검출된 뒷배경 사람은 추적하지 않는다.
- 로컬 VLM(mlx-vlm), Gemini 직접 호출, 일부 검출기 · 임베딩 후보는 어댑터가 없다(실험실 프로필 검사에 표시).
- 출력 파일에는 원본의 메타데이터가 그대로 남는다(설계대로). 위치(GPS) 태그가 있으면 보고서 고지에 적는다. 지울지는 정하지 않았다.
- Dolby Vision은 보존하지 못하고(검증에서 실패로 나옴), 코덱 없는 데이터 트랙(Apple `mebx`, GoPro `gpmd`)은 복사되지 않는다. iPhone HDR · 회전 · 가변 프레임레이트 실촬영본으로는 확인하지 못했다(합성 클립으로만 확인). U5는 그래서 부분 확인이다.
- U3(사전 블러가 설명 품질을 떨어뜨리는가)와 U7(검색 구성 비교)은 측정하지 않았다. 평가 데이터와 코퍼스가 정해져야 한다.
- 옛 1.0 백엔드(`privframe.api`, `adapters/`, `application/` 등)는 그대로 두었다. 새 코드와 서로 import하지 않는다. 옛 테스트는 OpenCV 영상 입출력을 써서 PyAV와 한 프로세스에 두면 libx265 테스트가 죽으므로 `backend/tests/legacy`로 옮겨 따로 실행한다.
