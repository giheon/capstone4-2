## 1. 배경

- M3에서 수집, 원문 저장, 분할, 색인, 검색 도구를 만들고 실제 자료 12건으로 수집부터 LLM 도구 호출과 LangSmith 추적까지 동작을 확인했다. 도구는 특정 자료 목록에 묶여 있지 않다.
- M4에서 실제 코퍼스를 모으려면 무엇을, 어떤 기준으로, 얼마나 넣을지부터 정해야 한다. 이 기록은 그 정의를 한곳에 모으고 팀이 정할 항목을 분리한다.
- 이미 정해진 전제 (2026-11-11)
  - 원문만 쓴다. 판례 요약 카드는 만들지 않는다.
  - 사람이 검토하는 단계를 두지 않는다. 선별, 표시, 검사는 규칙과 LLM이 하고 근거를 자동으로 남긴다.
  - 부족한 품질은 코퍼스를 손으로 다듬기보다 LLM과 RAG 성능을 높여 보완한다.

## 3. 범위

### D1. 범위 기준

> 그 문서가 **가림 결정**(무엇을, 어떻게, 어느 구간을, 어떤 예외로)이나 **그 근거 설명**을 바꿀 수 있으면 범위 안, 아니면 범위 밖이다.

- 이유: 시스템의 출력은 가림 계획과 그 근거다. 출력을 바꾸지 못하는 문서는 검색 잡음만 늘린다.
- 판정은 사람이 아니라 D10의 LLM 관련성 채점이 한다.

### D2. 답해야 할 질문 9개

| # | 질문 | 주된 규범 | 주된 사례 |
|---|---|---|---|
| Q0 | 어느 법 체계가 적용되나 (업무 목적의 개인정보처리자인가, 사적 촬영인가) | 개인정보 보호법 제2조, 제58조 | 개인정보처리자 해석 사례 |
| Q1 | 이것이 개인정보인가 (얼굴, 전신, 번호판, 명찰, 단서의 결합) | 법 제2조제1호, 제58조의2, 표준지침 제2조 | 식별 가능성 사례 |
| Q2 | 촬영과 수집이 허용되나 (고정형, 이동형, 공개 장소) | 법 제15·22·25·25조의2, 시행령 제22~27조 | 영상기기 관련 결정문, 해석례 |
| Q3 | 공개와 제공이 허용되나 (제3자 제공, 목적 외, 공개 범위) | 법 제17·18·19조 | 제공, 공개된 개인정보 사례 |
| Q4 | 동의는 어디까지인가 (촬영 동의와 공표, 묵시적 동의) | 법 제22조 | 2021다219116 |
| Q5 | 더 보호되는 대상과 장소 (아동, 민감정보, 사생활 장소) | 법 제22조의2·23조·25조제2항 | 관련 결정문 |
| Q6 | 예외와 이익형량 (언론·공익, 증거 확보, 공적 인물) | 헌법 제10·17·21조, 민법 제750·751조, 언론중재법 제5조 | 2020다227455, 2020다253423 |
| Q7 | 어느 수준까지 가려야 하나 (가명, 익명, 가린 뒤 남는 단서) | 법 제2조제1호의2, 제28조의2, 제58조의2 | 주로 안내서 |
| Q8 | 정보주체의 요청 (열람 요청 때 타인 가림) | 법 제35조, 표준지침 영상 조항 | 헌재 2015헌마994 |

- 이 질문 목록은 수집의 기준이자 평가 질문의 분류 기준이다. 질문을 늘리면 코퍼스도 늘어난다.
- Q0이 중요한 이유: 개인 사용자는 개인정보처리자가 아닐 수 있고, 그때는 초상권 법리가 주된 근거가 된다. 초상권 판례는 참조조문이 개인정보 보호법이 아니라서 찾는 경로가 따로 필요하다(D9의 ③).
- 표의 조문 번호 중 리서치에서 확인하지 않은 것(법 제18·19·35조, 헌법 제21조, 언론중재법 제5조)은 수집할 때 현행 원문으로 확인한다.

### D3. 범위 밖과 보류

| 구분 | 대상 | 이유 |
|---|---|---|
| 범위 밖 | 음성·녹음, 과징금·벌칙 산정, 안전조치·유출 통지, 국외이전·위탁, 가명정보 결합 절차, 분쟁조정 절차, 저작권, 외국법(GDPR 등) | 영상 가림 결정을 바꾸지 않는다 |
| 보류 | 범죄 피해자·소년의 신원 보도 금지 조항, 유명인 초상의 상업적 이용 | 해당 시나리오가 생기면 넣는다 |

- 실행 중 범위 밖 쟁점이 나오면 에이전트가 "근거 부족"으로 표시하고 추가 수집 후보 목록에 자동으로 기록한다. 코퍼스를 늘릴지는 이 기록을 보고 다음 버전에서 정한다.

| 종류 | 예 | 출처 | 권위 |
|---|---|---|---|
| 법령 | 개인정보 보호법, 시행령, 헌법·민법의 해당 조문 | 국가법령정보 API (`law`) | 1 |
| 행정규칙 | 표준 개인정보 보호지침 | API (`admrul`) | 1 |

| 안내서 | 고정형·이동형 영상기기, 가명정보, 아동, 생체정보 | 개인정보위 게시판 PDF | 3 |

### D5. 권위 등급 (기존 설계 유지)

| 등급 | 뜻 | 해당 종류 |
|---|---|---|
| 1 규범 | 지켜야 하는 규정 | 법령, 행정규칙 |
| 2 해석 | 규범을 해석하거나 적용한 판단 | 판례, 헌재 결정, 해석례, 개인정보위 결정문 |
| 3 참고 | 구속력 없는 실무 기준 | 안내서, 분쟁조정 사례집 |

- 규칙: 등급 1이나 2의 근거 없이 등급 3만으로 "의무"를 단정할 수 없다. 판례만으로 "의무"를 단정하지 않는다. 검증기가 확인한다.
- 같은 등급 안의 순서(전원합의체 > 대법원 > 하급심)는 D10의 우선순위에서 쓴다.

### D6. 시점과 판본

- 법령과 행정규칙은 **수집 기준일의 현행본**만 색인한다. 시행 예정본과 과거 판본은 받지 않는다. 지금 기준은 개인정보 보호법 법률 제21445호(2026-09-11 시행)다.
- 부칙은 시행일만 기록하고 색인하지 않는다. 별표는 넣지 않는다.
- 안내서는 같은 제목의 최신판만 쓰고 구판은 교체한다.
- 판례는 선고일과 상관없이 넣되, 이후 판결로 변경된 것은 D10의 유효성 검사로 가린다.

### D7. 문서의 단계와 양

| 단계 | 뜻 | 세는 것 |
|---|---|---|
| 후보 | 목록에만 있음 | 경로별 후보 수 |
| 채택 | 원문을 받아 보관함 | 채택 수, 탈락 사유별 수 |
| 색인 | 검색 대상 | 문서 수, 청크 수 |
| 전달 | 한 번의 질문에서 LLM에 들어감 | 검색 결과 수와 토큰 수 (프로필의 검색 설정이 정함) |

- 원문은 채택되면 모두 보관하고, 색인할지는 따로 정한다(M3 도구의 `index: false`).
- 양은 미리 건수를 정하지 않는다. 기준(D10)을 정하고, 그 기준으로 나온 건수를 실측한다.

### D8. 분할 단위

| 종류 | 단위 | 청크 머리말 (원문 항목에서 규칙으로 생성) |
|---|---|---|
| 법령, 행정규칙 | 조 (긴 조는 항으로 나눔) | `개인정보 보호법 › 제25조의2(이동형 영상정보처리기기의 운영 제한)` |
| 판례, 헌재 결정 | 판시사항, 판결요지, 이유의 단락 | `대법원 2023. 4. 13. 선고 2020다253423 판결 · 손해배상 · 주문: 파기환송 · 3.나.` |
| 해석례, 결정문 | 질의요지, 회답, 판단 | 기관, 일자, 사건명 |
| 안내서, 사례집 | 제목 구간 (못 나누면 쪽) | 안내서 이름, 판, 제목 경로, 쪽 |

- 머리말에는 원문에 있는 항목만 쓴다. 요약문은 만들지 않는다.
- 주문(파기환송, 상고기각 등)을 판결문의 모든 청크 머리말에 넣는다. 2020다253423 오용처럼 결론과 반대로 인용되는 일을 줄이기 위해서다.

## 5. 판례 선정

### D9. 판례를 찾는 경로

| 경로 | 방법 | 이유 |
|---|---|---|
| ① 기관이 고른 목록 | 개인정보위 판례집, 안내서와 결정문 모음집에 인용된 판례 | 전문기관의 선별에서 출발 |
| ② 참조조문 | 판례 API에서 참조조문이 개인정보 보호법인 판례 | 법 해석 판례를 빠짐없이 |
| ③ 주제어 | 초상권, 개인영상정보, 영상정보처리기기, CCTV 열람, 촬영 동의, 블랙박스 등 | 초상권 판례는 ②로 잡히지 않음 |
| ④ 인용 따라가기 | 채택 판례가 인용한 판례와 그 판례를 인용한 이후 판례, 두 단계까지 | 기준 판례와 이후 변화를 함께 확인 |

- 종료 조건: ④를 한 단계 더 돌려도 새로 채택되는 판례가 없으면 끝낸다.
- 한계: law.go.kr에 실린 판례 안에서의 전수다. 하급심은 실린 양이 적다.
- 이미 나온 인용 후보: 2010다103185, 2015다33489, 96다42789, 2004다16280, 2012다31628.

### D10. 판례 채택 기준 (모두 자동)

| 단계 | 방법 | 남기는 기록 |
|---|---|---|
| 1. 규칙 거르기 | 법원급, 사건 종류, 주제어가 판시사항·판결요지·판단 부분에 있는지 | 통과하거나 탈락한 규칙 |
| 2. 관련성 채점 | LLM이 원문을 읽고 Q0~Q8 가운데 어디에 답하는지와 점수를 매김 | 연결된 질문, 점수, 사용한 모델 |
| 3. 유효성 검사 | 이후 전원합의체 판결에 "변경하기로 한다"와 해당 사건번호가 함께 있는지 | 변경 문구 발견, 발견 못 함, 검사 못 함 |
| 4. 우선순위 | 전원합의체 > 대법원 > 하급심. 같은 급이면 후보 안에서 인용된 횟수 순 | 급, 인용 횟수 |

- 질문마다 결론이 다른 사례(침해 인정, 침해 부정)가 모두 있는지 자동으로 집계한다. 한쪽이 없으면 주제어를 넓혀 다시 찾는다.
- 최신성은 선정 기준이 아니다. 급과 점수가 같을 때만 최신을 앞에 둔다.
- 해석례와 결정문도 1, 2단계를 같은 방식으로 거친다.

### D11. 판결문 단락의 역할

| 구분 | 내용 | 처리 |
|---|---|---|
| 기본 검색 | 판시사항, 판결요지, 이유 중 그 법원의 법리와 판단 | 색인 |
| 표시 후 기본 검색에서 제외 | 원심 판단 요약, 당사자 주장, 반대·별개·보충의견 | "원심", "소수의견"으로 표시하고 색인은 하되 기본 검색에서 뺌 |
| 보관만 | 당사자 표시, 절차, 소송비용 | 색인 안 함 |

- 역할은 제목 규칙으로 가리고, 규칙으로 못 가리는 단락만 색인할 때 LLM이 표시한다.

## 6. 버전, 평가, 오용 방지

### D12. 코퍼스 버전

| | v1 | v2 |
|---|---|---|
| 판례, 헌재 | 대법원과 헌재만, 관련성 임계값 엄격 | 하급심 포함, 임계값 완화 |
| 해석례, 결정문 | 영상 관련만, 임계값 엄격 | 임계값 완화 |
| 법령, 안내서 | 같음 | 같음 |

- 버전은 건수가 아니라 규칙으로 정의한다.
- 버전 ID는 목록 규칙, 수집 기준일, 문서별 해시로 만든다. 실행 기록, 실험 기록, LangSmith 추적에 버전 ID를 남긴다.
- 실행 중에는 로컬에 보관한 원문만 조회한다. 외부 API를 실행 중에 부르지 않는다.

### D13. 충분성 판단

| 지표 | 뜻 |
|---|---|
| 정답 근거 재현율 | 평가 질문의 정답 근거가 검색 상위 k개 안에 드는 비율 |
| 인용 충실성 통과율 | 인용한 단락이 주장을 실제로 뒷받침하는 비율 (D14) |
| 가림 결정 F1 | 최종 가림 계획이 정답과 맞는 정도 (기존 실험 게이트의 지표) |
| 비용 | 한 실행의 LLM 입력 토큰과 금액 |

- v1과 v2를 같은 검색 설정으로 비교한다.
- 평가 질문은 팀 시나리오와, 원문 단락에서 LLM이 자동으로 만든 질문·근거 쌍(합성으로 표시)을 쓴다. 임계값을 정할 때 쓰지 않은 질문을 따로 떼어 둔다.
- 오용 회귀 질문을 둔다. 예: 명찰 가림의 근거를 묻는 질문에 2020다253423이 "가려야 한다"의 근거로 인용되면 실패.
- 실패 원인을 세 가지로 나눠 기록한다: 코퍼스에 없음, 있는데 못 찾음, 찾았는데 잘못 적용.

### D14. 실행 중 오용 방지

1. **열람 의무**: 판례를 근거로 인용하려면 그 판결의 주문과 판단 부분을 `get_document`로 열어 봤어야 한다. 검증기가 도구 호출 기록으로 확인한다.
2. **인용 충실성 검사**: 분석가와 다른 회사의 모델이 주장, 인용 단락, 주문과 판단을 받아 "뒷받침 / 무관 / 반대 방향"을 판정한다. 프로필 부품 `llm.citation_checker`로 추가한다.

- 감수하는 위험: 사람 검토가 없으므로 자동 선별과 LLM 판정의 오류는 평가 실험에서만 드러난다. D13의 지표와 오용 회귀 질문이 그 안전장치다.
