## 12. 법률 코퍼스 수집 계획 — 초안 2 (M4-1에서 확정, 미확정)

상태: **설계 초안.** 2026-11-11 사용자 검수에서 방향만 정해졌다(판례 카드와 사람 검토 없이 원문만 사용, 선별 자동화). 최종 선정 기준, 규모, 검색 성능 최적화는 M4-1에서 정한다. M3에서 만든 수집·저장·색인·검색 도구는 이 초안의 기준이나 목록에 묶여 있지 않다([11-tool-setup.md](./11-tool-setup.md)).

원칙: 판례 카드와 사람 검토 없이 원문만 쓴다. 선별은 규칙과 LLM으로 자동화하고, 판례 오용은 색인 방식과 실행 중 검사로 막는다.

### B. 공통 원칙

1. **범위 기준**: 그 문서가 가림 결정(대상·방식·구간·예외)이나 그 근거 설명을 바꿀 수 있으면 범위 안, 아니면 밖.
2. **양은 네 단계로 따로 관리**: 후보(목록만) / 채택(원문 보관) / 색인(검색 대상) / 전달(LLM 입력).
3. **원문만 쓴다.** 청크에 붙는 정보는 원문 자체의 항목(법원, 선고일, 사건번호, 주문, 단락 위치)뿐이다.
4. **사람 검토 단계가 없다.** 선별·표시·검사는 규칙과 LLM이 하고 근거를 자동으로 기록한다. 품질은 평가 실험으로 확인한다.
5. 코퍼스는 버전으로 고정하고 실행·실험 기록에 버전을 남긴다. 실행 중에는 로컬 원문만 조회한다.

### E. 사례

**찾는 법 (네 경로로 후보를 모아 중복 제거)**

| 경로 | 방법 | 왜 |
|---|---|---|
| ① 기관이 고른 목록 | PIPC 개인정보보호 판례집, 안내서·결정문 모음집에 인용된 판례 | 전문기관의 선별에서 출발 |
| ② 참조조문 검색 | 판례 API에서 참조조문이 개인정보 보호법인 판례 | 법 해석 판례를 빠짐없이 |
| ③ 주제어 검색 | 초상권, 개인영상정보, 영상정보처리기기, CCTV 열람, 촬영 동의, 블랙박스 등 | 초상권 판례는 ②로 안 잡힘 |
| ④ 인용 따라가기 | 채택 판례가 인용한 판례와 그 판례를 인용한 이후 판례, 두 단계까지 | 기준 판례와 이후 변화 확인 |

- 끝내는 조건: ④를 한 단계 더 돌려도 새로 채택되는 판례가 없으면 종료.
- 한계: law.go.kr 수록 범위 안에서의 전수다. 하급심은 수록이 적다.
- 판결문 3건에서 이미 나온 인용 후보: 2010다103185, 2015다33489, 96다42789.

**고르는 기준 (전부 자동)**

| 단계 | 방법 | 기록 |
|---|---|---|
| 1. 규칙 거르기 | 법원급, 사건 종류, 주제어가 판시사항·판결요지·판단 부분에 있는지 | 통과·탈락 규칙 |
| 2. 관련성 채점 | LLM이 원문을 읽고 질문 0~8 중 어디에 답하는지와 점수를 매김 | 연결 질문, 점수, 모델 |
| 3. 유효성 검사 | 이후 전원합의체 판결의 "변경하기로 한다" 문구에 해당 사건번호가 있는지 | 변경 문구 발견 / 발견 못 함 / 검사 안 함 |
| 4. 우선순위 | 대법원 전원합의체, 대법원, 하급심 순. 같은 급이면 후보 안에서 인용된 횟수 순 | 급, 인용 횟수 |

- 질문마다 주문 방향이 다른 사례가 모두 있는지 자동 집계하고, 한쪽이 없으면 검색어를 넓힌다.
- 최신성은 선정 기준이 아니다. 같은 급·같은 점수일 때만 최신을 우선한다.

**저장과 색인**

| 구분 | 내용 | 처리 |
|---|---|---|
| 색인 | 판시사항, 판결요지, 이유 중 해당 법원의 법리·판단 단락 | 단락 단위 청크 |
| 표시 후 기본 검색 제외 | 원심 판단 요약, 당사자 주장, 반대·별개·보충의견 | "원심(파기 여부)", "소수의견"으로 표시 |
| 보관만 | 당사자 표시, 절차, 소송비용 | 색인 안 함 |

- 모든 청크의 머리말(원문 항목에서 규칙으로 생성): `대법원 2023. 4. 13. 선고 2020다253423 판결 · 손해배상 · 주문: 파기환송 · 3.나. 판단`.
- 단락 역할은 제목 규칙으로 가리고, 못 가리는 단락만 색인 때 LLM이 표시한다. 요약문은 만들지 않는다.

**실행 중 오용 방지**

1. 열람 의무: 판례를 근거로 인용하려면 그 판결의 주문과 판단 부분을 `get_document`로 열람했어야 한다. 검증기가 도구 호출 기록으로 확인한다.
2. 인용 충실성 검사: 분석가와 다른 회사의 모델이 "주장, 인용 단락, 주문·판단"을 받아 뒷받침 / 무관 / 반대 방향을 판정한다. 프로필 부품 `llm.citation_checker`로 추가한다.
3. 판례만으로 "의무"를 단정하지 않는다는 기존 규칙(설계 §9.1)은 유지한다.

감수하는 위험: 자동 선별과 LLM 판정의 오류는 평가 실험에서만 드러난다.

**양과 평가**

| | v1 | v2 |
|---|---|---|
| 판례·헌재 | 대법원·헌재만, 관련성 임계값 엄격 | 하급심 포함, 임계값 완화 |
| 해석례·결정문 | 영상 관련, 임계값 엄격 | 임계값 완화 |

- 건수는 규칙으로 정하고 실측한다. v1과 v2를 같은 검색 설정으로 비교한다: 정답 근거를 찾는 비율, 인용 충실성 통과율, 최종 가림 결정, 비용.
- 평가 질문: 팀 시나리오와, 원문 단락에서 LLM이 자동 생성한 질문·근거 쌍(합성 표시). 임계값을 정할 때 쓰지 않은 질문을 따로 떼어 둔다.
- 오용 회귀 질문: 명찰 가림 근거를 묻는 질의에 2020다253423이 "가려야 한다"의 근거로 인용되면 실패.
- 실패 원인 구분: 코퍼스에 없음 / 있는데 못 찾음 / 찾았는데 잘못 적용.

### F. M4-1에서 정할 것

1. 연결 조문(헌법·민법·언론중재법)을 넣을지, 보류 목록에 동의하는지.
2. 하급심을 v2에서만 넣을지.
3. 인용 충실성 검사를 파이프라인 부품으로 추가할지.
4. 관련성 채점에 쓸 모델(경량 모델 제안).
