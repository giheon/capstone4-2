# PrivFrame 2.0 — 설계·PRD v2 (승인본)

작성 2026-11-05 · v1 초안(같은 날)에 대한 사용자 반려 지시 반영 · 상태 **승인됨(2026-11-05, 임기헌)** · 기준 코드 `feat/person-aware-workflow@c03476e`

> 설계 원칙: "현재 구현을 어떻게 확장할 것인가"가 아니라 "달성하려는 목표를 가장 잘 만족하는 시스템은 무엇인가"에서 출발한다. 기존 코드·Notion 문서는 목표·결정 이력·현황을 아는 자산이며, 아래 모든 결정은 **유지 / 부분 개선 / 전면 교체**를 비교해 고른 결과다. 다이어그램 9장은 렌더링 페이지(아래 '다이어그램과 검증'의 링크)로 제공하고, 본문 Mermaid 소스와 동일한지 검증했다.

## 0. 요약

- **무엇이 바뀌었나(v1 → v2)**: ① 고정 선택지 입력을 폐기하고 **에이전트가 생성하는 동적 질문 + 개방형 Fact 모델**로 교체 ② **원본 스트림 렌더**(프록시는 분석 전용, PTS 맵으로 복귀)로 "비식별 영역 외 동일" 요구를 충족 ③ "쟁점 생성 → 검색 → 판단" 선형 순서와 고정 택소노미를 버리고 **도구를 쓰는 Legal Analyst 에이전트 루프**(검색·열람·시각 점검·질문·종결을 상태에 따라 선택)로 교체, 택소노미는 **누락 점검 체크리스트·평가 라벨**로만 사용 ④ 얼굴 사전 블러를 "기본값"에서 **비교 실험 대상(3안)** 으로 격하하고 선택 근거를 명시 ⑤ 팀 작성 유사사례를 **법률 코퍼스에서 제외**(평가 데이터셋으로 이동), 코퍼스를 권위 등급·시행일 메타데이터로 재구성 ⑥ 멀티에이전트를 "노드 분할"이 아니라 **동적 판단이 필요한 2곳(Legal Analyst·Auditor)에만 에이전트, 나머지는 결정적 도구·검증 노드**로 정의하고 종료 조건·안전장치를 명시.
- **유지한 것**: 포트/어댑터 분리, 프로필(YAML) 주입, artifact fingerprint 캐시·실행 기록·supersede, 얼굴 검출(YuNet)·장면 경계·인물 그룹화 알고리즘, FastAPI+Celery+React 골격, 리서치로 선정한 모델·도구(§10).
- **일정**: M4(11/13) = 세로 슬라이스(지각 확장 + Legal Analyst 루프 + 동적 질문 1라운드 + Planner + 원본 품질 렌더 + 보고서 v1 + LangSmith), M5(11/20 시연) = Review Guide·Auditor·베이스라인·반사실 실험·팀 테스트 케이스. 일정은 설계 품질보다 우선하지 않으며, 부족하면 M4 범위를 줄이되 구조는 유지한다(§13.4).
