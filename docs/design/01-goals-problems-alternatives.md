### 1.2 기존 문서·코드의 임의 선택 (구속력 없음)

목적 11·공개범위 6 고정 선택지와 인물별 관계/동의 필드(10/07 "자율서술 제거" 결정의 취지는 **자유서술을 검색 질의로 쓰지 말라**는 것이지 사실 수집을 폼으로 고정하라는 것이 아님), 얼굴 전용 검출, 30 fps CFR 정규화와 정규화본 렌더, 단일 질의 검색·1200/150 청킹·OpenAI 임베딩, 트랙 단위 KEEP/BLUR/MOSAIC/MASK 계약, 선형 GraphRunner, 비즈니스 상태로만 구현한 사용자 대기, v1 초안의 고정 택소노미 I01~I17·얼굴 사전 블러 기본값·팀 유사사례 코퍼스·"쟁점 → 검색 → 판단" 선형 순서.

### 1.3 검증된 기술적 사실 (코드 확인·1차 출처 리서치)

> 여기서 "현재" 코드와 `adapters/…` 경로는 설계 시점의 1.0 코드다. 1.0 코드는 2026-11-12에 저장소에서 지웠고 커밋 `c03476e`에서 볼 수 있다.

- 현재 `analyze`는 입력을 `fps=30` CFR·`libx264 -crf 18`·`yuv420p`·AAC 128k로 재인코딩한 프록시를 만들고, `render`는 그 프록시 프레임을 다시 `libx264 -crf 18` CFR로 인코딩한 뒤 **프록시의 오디오**를 붙인다(`adapters/vision.py:379-383, 562-618`). 즉 출력은 입력과 fps·타이밍·픽셀 포맷·오디오·메타데이터가 다르다 → G8 위반 확정.
- 모델·API·법령 사실은 §10·§11의 리서치 표(1차 출처 링크) 기준: LangGraph 1.2.20/LangSmith 0.14.17 API, OpenRouter의 영상 입력·구조화 출력·ZDR 범위, 한국어 법률 검색 벤치마크(LawIRKo)에서 KURE 계열 우위, PP-OCRv5 한국어 88%, RF-DETR Apple CoreML 지연, law.go.kr Open API 조문·판례·PIPC 결정문 엔드포인트, 현행 개인정보 보호법 제21445호(시행 2026.9.11), 판례 5건의 판시.
- 영상 I/O 사실(R7, FFmpeg 공식 texinfo·소스, PyAV 19.0.2 문서·소스, OpenCV 소스, ffmpeg 9.0.2 로컬 왕복 테스트): `-fps_mode passthrough` + `-enc_time_base demux`가 VFR PTS를 그대로 보존하고, 기본 인코더 타임베이스(1/framerate)는 PTS를 반올림해 중복 PTS까지 만든다; `-autorotate` 기본값은 픽셀을 회전시키고 Display Matrix를 버린다; `-c:a copy`면 오디오 framemd5가 동일하다; rawvideo 디먹서에는 타임스탬프가 없다(현재 렌더 파이프가 VFR을 재현할 수 없는 이유); OpenCV의 `CAP_PROP_POS_FRAMES` 탐색은 CFR을 가정한다(`adapters/track_editing.py:17`이 사용). 상세는 §6.2·§6.4·§10.7.

## 3. 구조적 대안 비교와 결정

### 3.1 전체 구조 대안

| 기준 | **Arch-A** 워크플로+LLM 단계(v1) | **Arch-B** 단일 자율 에이전트(모든 도구) | **Arch-C** 오케스트레이션된 전문 에이전트(결정적 골격 + 동적 지점에만 도구 사용 에이전트) | Arch-D 규칙 엔진+LLM 설명(교수 반례, 베이스라인) |
