# PrivFrame 2.0 — M4 보완 기록

## 15. M4 보완 (2026-11-11)

M4 검수에서 나온 지시 8건 가운데 7건을 반영한 기록이다. 4번 지시는 문장이 중간에 끊겨 있어 반영하지 못했다. 8번(Celery는 M6, 판례 오용은 M4-1)은 하지 않는 일을 확인한 것이라 변경이 없다.

### 15.2 Claude API 경로와 비용 상한

- **어댑터**: 카탈로그에 `anthropic`(Anthropic API 직접)을 더했다. 대화 모델은 `langchain-anthropic`의 `ChatAnthropic`, 프레임이 들어가는 VLM 호출은 Anthropic SDK를 직접 쓴다(이미지가 LangSmith 추적에 남지 않게 하려는 기존 원칙). 키는 `.env`의 `ANTHROPIC_API_KEY`.
- **후보**: `claude-opus-5-5-api` · `claude-sonnet-5-5-api` · `claude-haiku-5-5-api`를 LLM 5개 부품과 VLM 3개 부품에 등록했다. 단가는 Anthropic 정가(Opus $4/$20, Sonnet $2/$10, Haiku $0.10/$0.50, 100만 토큰당).
- **프로필 `claude-api`**: baseline-v2에서 API 모델만 Claude로 바꾼 조합이다. 분석가는 설계가 정한 Sonnet 5.5 그대로이고(경로만 다름), 계획자와 VLM은 Opus 5.5다. 로컬 부품(검출 · 추적 · OCR · 임베딩 · 리랭커)은 같다.
- **모델별 처리**
  - Opus 5.5 · Sonnet 5.5는 사고(thinking)를 끌 수 없다. 깊이는 `effort`로 조절한다: 분석가 · 계획자 medium, VLM low. 사고 토큰이 출력 한도에 들어가므로 `max_tokens`는 16,000.
  - 구조화 출력은 강제 도구 호출이 아니라 `output_config.format`(JSON 스키마)을 쓴다. 이 모델들은 강제 도구 호출을 받지 않는다.
  - 프롬프트 캐시는 요청 단위 표시 하나로 켠다. 측정: 분석가 4턴에서 입력 76,775토큰 중 52,763토큰이 캐시에서 읽혔다.
  - 거절 응답은 API가 다른 모델로 이어 가도록 요청에 표시한다(Opus · Sonnet). Haiku는 지원하지 않아 거절이면 오류로 처리한다.
  - 비용은 API가 금액을 알려 주지 않아 카탈로그 단가로 계산한다. 캐시 읽기 10%, 캐시 쓰기 125%로 계산하므로 Opus의 캐시 읽기(실제 5%)는 조금 높게 잡힌다.
- **비용 상한**: `case.cost_cap_usd`는 폭주를 막는 안전장치이고 비용 목표(NFR-02의 $0.25)와 다른 값이다. M4에서는 목표와 같은 $0.30이어서 정상 실행이 멈췄다($0.327에서 멈춘 기록). 기본값을 $1.00으로 올렸고(범위 0~$20, 0이면 상한 없음), 프로필별로 baseline-v2 · local-only $1.00, budget-saver $0.30, claude-api · research-max $3.00이다. 멈춘 케이스를 상한을 올려 이어 가는 동작은 그대로다.
- **프로필 검사**: API 부품의 키가 `.env`에 없으면 프로필에 오류로 표시한다.

### 15.3 처리 방식: 유지와 모자이크

- 계약: `Method = keep | mosaic | remove`. `remove`는 파일 메타데이터 대상 전용이다(§15.5).
- 계획 모델(Planner)의 출력에서 방식 선택지 · 형태 · 구간 · 대안이 빠졌다. 모델은 대상 · 범위 · 가릴지 여부 · 충족 요건 · 이유만 적는다. 형태는 대상의 종류(얼굴 타원, 그 밖 사각형)에서, 구간은 요건과 추적 결과에서 코드가 정한다.
- 렌더는 모자이크 한 경로만 있다. 블록 수는 짧은 변 기준 6개(글자 · 번호판은 2.5배 큰 블록)로 M4 측정값 그대로다.
- 삭제한 것: 흐림 · 단색 가림의 렌더 코드와 상수, 화면의 방식 선택지와 미리보기 그리기, 결정의 `alternatives`, 계획 프롬프트의 방식 설명, 모의 백엔드의 해당 데이터.
- 2026-11-11 이전의 완료 케이스에는 흐림 기록이 남아 있고 고치지 않았다. 검토 대기 중이던 케이스 1건(`case_1111095101_204c`)은 계획을 새 규칙으로 옮겼다(흐림 · 가림 → 모자이크, 구간 재계산). 옮기기 전 상태는 따로 보관했다.

### 15.4 가림 범위와 출력 검증

원인과 원칙은 [ADR-0012](../adr/0012-frame-exact-ranges-and-full-frame-verification.md)에 있다. 구현은 다음과 같다.

- `core/geometry.py`
  - `Timeline`: 프레임 시작 시각, 영상의 끝, 분석 간격, 장면 경계. 구간에 속하는 프레임(`frames`), 프레임 묶음의 구간(`ranges`), 프레임 정렬(`align`), 경계 맞춤(`snap`)을 여기서만 한다.
  - `cover(영상 이해, 대상, 범위, timeline)`: 대상이 가려지는 프레임과 영역. 표본 사이 보간, 등장 앞뒤 여유, 1.5초 이하 공백 잇기, 컷 넘지 않기.
  - `build_regions`: 결정의 적용 구간 안 모든 프레임에 영역을 만든다. 추적된 영역이 없는 프레임은 가장 가까운 영역을 유지한다.
- 영상 이해(`understanding.json`)에 `visible`("대상:범위" → 구간)을 저장해 계획 · 감사 · 화면이 같은 값을 읽는다.
- 검토 미리보기: `GET/POST /api/cases/{id}/geometry`가 결정마다 프레임별 영역을 돌려준다. 화면은 보간 · 여유 계산을 하지 않고 받은 영역을 그린다. 수정 중인 계획은 POST로 보내 같은 계산을 받는다.
- 출력 검증의 행(고정 순서)

| 행 | 범위 | 실패 조건 |
|---|---|---|
| 프레임 수 · PTS 목록 · 오디오 framemd5 · 메타 · 픽셀 포맷 | 전체 | 원본과 다름(계획이 삭제한 태그는 제외) |
| 처리 영역 밖 PSNR-Y / SSIM | 전체 프레임 / 표본 | 38 dB · 0.97 미만 |
| VMAF | 전체 | 참고 수치 |
| **모자이크 적용** | **전체 프레임** | 계획의 구간에서 계산한 프레임에 영역이 없거나, 출력의 그 자리가 모자이크보다 원본에 가까움 |
| 처리 영역 재식별 | 처리 프레임 표본 120 | 영역 안 얼굴이 원본과 유사도 0.50 이상, 글자 재인식 0.5 이상 |
| **모자이크한 대상의 노출** | **전체 프레임, 화면 전체** | 영역 밖의 얼굴이 가린 인물의 원본 얼굴과 유사도 0.50 이상, 가린 글자가 영역 밖에서 판독됨(경계 프레임 + 표본 24) |
| 위치 메타데이터 삭제 | 삭제 결정이 있을 때 | 위치 태그가 남음 |

- 노출이 나오면 `verify_output → render_original`로 돌아가 그 자리를 더 가린다(최대 2회). 토폴로지에 이 간선이 추가되었다.
- 측정(예시 영상 10초, 모자이크): 영역 안 얼굴의 원본 대비 최대 유사도 0.06~0.08(흐림일 때 0.31~0.37), 영역 밖 얼굴과 가린 인물의 최대 유사도 0.19~0.22, 검증 12초.

### 15.5 위치 메타데이터

- `video.probe`가 컨테이너 · 스트림 태그에서 위치 태그(`location`, `location-eng`, `com.apple.quicktime.location.ISO6709` 등 이름에 location · gps가 든 것)를 찾아 `VideoMeta.location_tags`에 적는다.
- 태그가 있으면 대상 `meta-location`(촬영 위치 정보)이 생기고, 사실 `file.location_metadata = present`와 참고 패턴 P18(촬영 위치 메타데이터)이 분석가에게 전달된다. 좌표 값은 보내지 않는다.
- 분석가는 다른 대상과 같은 방식으로 근거를 찾아 요건(범위 `metadata`)을 내거나 유지 분석을 남긴다. 계획의 `remove` 결정이 있으면 렌더가 위치 태그만 빼고, 검증이 출력에 그 태그가 없는지 확인한다.
- 예시 영상에는 합성 위치 태그(서울시청 좌표)를 넣었다. 실제 실행에서 분석가는 "촬영 위치가 사적 장소인가"를 물었고, "공개된 장소"라는 답에서 한 번은 삭제 요건을, 한 번은 유지 결론을 냈다. 지금 시드 묶음에는 위치정보에 관한 조문이 없어(개인정보 보호법 제2조의 정의만 근거로 씀) 결론이 실행마다 달라질 수 있다. 근거 문서의 범위는 M4-1에서 정한다.

### 15.6 토폴로지 기록

- 오른쪽 패널의 상태 채널 · 이벤트 · 체크포인트 목록이 위에서 아래로 과거 → 최신 순이다(에이전트 메모리와 노드 탭의 목록은 원래 과거순).
- 실행 중에는 최신 기록을 따라가고, 위로 스크롤하면 멈춘다. "최신 기록으로" 버튼으로 다시 따라간다. 끝난 실행은 첫 기록에서 연다.
- 노드를 고르면 보고 있는 목록에서 그 노드의 첫 기록으로 스크롤하고, 그 노드(하위 노드 포함)의 기록에 왼쪽 막대와 굵은 글씨로 표시한다. 기록이 없으면 없다고 적는다. 같은 노드를 다시 누르면 그 위치로 돌아간다.

### 15.7 구간 실험

> 2026-11-12에 구간 실험의 모양이 바뀌었다(실행이 쌓이는 묶음, 자동 응답 없음, 구간 5개). 지금의 동작과 API는 [16-lab-runs-and-experiment-sets.md](./16-lab-runs-and-experiment-sets.md)를 본다. 아래는 2026-11-11 시점의 기록이다.

구성은 [ADR-0013](../adr/0013-section-experiments-by-checkpoint-fork-and-step-store.md)에 있다.

- **구간** (`core/stages.py`): 영상 정보 추출(`perceive`) · 법률 분석(`legal_analyst`) · 계획(`plan`~`review_guide`) · 렌더 · 검증(`render_original`~`report`). 구간마다 읽는 부품과 설정값이 정해져 있고, 실험은 이어진 구간 범위를 고른다. 단계마다 "결과가 의존하는 부품 · 설정값 · 앞 단계"를 적은 표(`STEPS`)가 하나 있고, 단계 결과 저장소의 키와 화면의 "다시 계산되는 단계" 표시가 모두 이 표에서 나온다.
- **조합**: 고른 부품의 후보들을 곱한 조합(최대 12개). 기준 프로필의 후보는 항상 선택지에 들어가므로, 두 부품에서 하나씩 고르면 각각만 바꾼 조합 둘과 둘 다 바꾼 조합이 나온다. 기준 프로필 그대로인 조합이 기준이다. 시작할 때 조합마다 프로필 검사를 돌려 실행할 수 없는 조합(없는 어댑터, 없는 키, V-3인데 외부 VLM)은 거절한다.
- **실행** (`service/experiments.py`): 영상마다 기준 실행 1회 → 조합마다 기준 실행의 체크포인트에서 분기(`RunManager.fork`) → 범위의 끝에서 멈춤. 실행은 보통의 케이스(`exp_…`)라서 토폴로지에서 열 수 있다.
- **단계 결과 저장소** (`core/artifacts.py`, `data/artifacts/`): 메모 사실 추출 · 프록시 · 검출 추적 · 인물 묶음 · OCR · 장면 설명 · 인물 속성. 실험이 아닌 실행에도 적용된다.
- **영상 데이터셋** (`service/datasets.py`, `data/datasets/`): 기본 `sample`(합성 예시 영상, 정답 포함)과 직접 만든 묶음(업로드 또는 기존 실행의 영상). 외부 전송 금지로 만든 묶음은 프레임을 외부 모델로 보내는 조합을 건너뛴다.
- **비교 지표**: 구간 시간, 재사용으로 아낀 시간과 비용(저장된 단계가 처음 계산될 때 든 값), 비용, 모델 호출 수, 단계별 실행/재사용, 구간의 산출물(찾은 글자 · 인물 · 번호판 · 장면과 장면별 장소 · 사람 수 / 요건의 대상 / 결정의 대상 / 검증 통과), 기준과의 일치도와 다른 점, 정답이 있으면 정답 대비 점수. 화면은 "구간을 처음부터 계산하면"(재사용분을 원래 값으로 더한 것)과 "이번 실행에서 쓴 것"을 나눠 보여 준다: 재사용 여부는 실행 순서에 달려 있어서, 쓴 시간만으로 조합을 비교하면 안 된다.
- **API**: `GET /api/lab/sections`(구간과 단계 표), `GET · POST /api/lab/stage-experiments`, `GET /api/lab/stage-experiments/limits`, `GET · DELETE /api/lab/stage-experiments/{id}`, `POST …/{id}/stop`, `GET · POST /api/lab/video-sets`, `GET · PATCH · DELETE /api/lab/video-sets/{id}`, `…/{id}/items`(업로드), `…/{id}/items/from-case`, `PATCH · DELETE …/{id}/items/{item}`, `GET /api/lab/artifacts`. `POST /api/lab/runs/{id}/fork`는 이제 체크포인트에서 이어 간다(FR-14). 실행 요약(`GET /api/lab/runs`)에 분기 원본 · 분기 노드 · 멈춘 노드 · 실험 · 조합이 들어간다.
- **안전장치**: 실험 전체 비용 상한(기본 $5), 조합 12개 · 실행 60건 상한, 실행할 수 없는 조합은 시작할 때 거절, 기준 프로필이 프레임을 외부로 보내는데 외부 전송 금지 데이터셋을 고르면 거절(다른 조합이 모두 기준 실행에서 분기하기 때문), 외부 전송 금지 영상에서는 프레임을 보내는 조합만 건너뜀.

### 15.9 알려진 한계

- 4번 지시는 반영하지 못했다.
- 판례 2020다253423의 오용은 그대로다(M4-1). Claude 프로필의 실행에서도 같은 인용이 나왔다.
- 위치 메타데이터의 결론은 근거 문서가 부족해 실행마다 달라질 수 있다(§15.5).
- 글자의 화면 전체 판독은 표본이다. 얼굴 대조는 가린 인물과 닮은 유지 대상을 노출로 볼 수 있다(가리는 쪽으로 틀림).
- 단계 결과 저장소는 같은 입력의 VLM 출력을 다시 쓴다. 모델 출력의 변동은 재지 못한다.
- 구간 실험의 정답 비교는 지각 결과에만 있다. 법률 분석 · 계획의 정답 채점과 회귀 게이트는 M5다.
- 로컬 VLM(V-3) 어댑터는 여전히 없다.
- 옛 1.0 코드는 그대로 두었다(흐림 관련 코드 포함).
- 검토자는 등장 · 퇴장 시점에서 0.5초 안쪽으로는 구간을 줄일 수 없다(그 시점으로 맞춰진다). 화면이 실제 적용 구간을 보여 준다.
- 식별 · 질문 화면의 정지 화면은 대상의 위치를 임시 결정으로 물어 얻는다(대상 기준 조회가 없다). 동작에는 문제가 없다.
- 분석가 · 계획 모델의 조합을 바꾸는 실험에서, 실험할 수 없는 부품이 있다: 윤곽 마스크, 검토 안내 · 감사 · 보고서 모델(M5에서 호출), 계획 전략, 비용 상한.
