# PrivFrame 베이스라인 구현·검증 결과

검증일: 2026-10-02 · CPU 실행 · 단일 사용자 / 한 호스트

업로드 → 추출·색인 → 얼굴 분석 → 검색·판단 → 사용자 검토 → 영상·보고서 출력까지 연결했다. 모델과 알고리즘은 초기 기본값이며, 교체와 비교를 위한 공통 계약을 유지한다. 실제 OpenAI 통신은 API 키가 없어 수행하지 않았다. 아래 영상·통합 검증에서는 **fixture 임베딩·판단과 실제 Chroma·검출·렌더**를 사용했다.

## 실제로 확인한 결과

### 문서·검색·판단

- 고정된 공식 manifest의 개인정보 보호법, 고정형 안내서, 이동형 안내서 **3개를 다운로드·추출**했다. 법률 시행일과 안내서 발간일, 출처와 원문 해시를 별도로 보존한다.
- PDF·TXT·공식 법령 HTML을 공통 `SourceUnit`으로 변환했다. 청크의 문서·페이지/조문·원문 offset·해시와 색인 설정을 저장한다.
- Chroma 영속 검색, 중단된 색인 재시도, 새 프로세스에서 같은 색인 조회를 검사했다. 청킹 설정이 다르면 호환되지 않는 색인의 사용을 거부한다.
- 검색 후보와 실제 판단 입력 근거를 구분했다. 모델 초기화·호출이 실패해도 이미 검색한 근거가 실행 기록에 남는다.
- 실제 LangChain/OpenAI SDK의 요청 직렬화는 `httpx.MockTransport`로 검사했다. Responses API, 지정 모델, strict JSON Schema, reasoning 설정과 구조화 응답 처리를 확인했다. **이 검사는 OpenAI 서버 실호출 검증이 아니다.**

### 영상·브라우저

- 공개 우주비행사 사진으로 만든 1초·오디오 포함 영상을 실제 YuNet으로 분석했다. 얼굴 **1개 / 정규화 30프레임**을 검출했다. Haar도 같은 얼굴을 검출했다. 이는 샘플 작동 확인이며 검출 정확도·recall 측정은 아니다.
- 네이티브 브라우저 흐름에서 공식 자료의 검색 근거 **8개**와 판단 입력을 보존하고, MASK 강도 2 출력·MP4 다운로드·SHA256·오디오·HTML/JSON 보고서를 확인했다.
- 완료한 결과를 **MOSAIC 강도 2**로 바꿔 새 실행에 출력했다. 새 실행에는 `render` 단계만 있으며, 관측·검색 근거·판단·입력 prompt를 재사용했다. 부모의 전체 snapshot과 영상·HTML/JSON 바이트는 그대로였다.
- Linux ARM64에서도 실제 YuNet 분석 → MASK 출력 → BLUR 강도 3 재출력과 오디오·파일 해시·보고서 일치를 확인했다. Linux 검증에는 별도의 fixture TXT 색인을 사용했다.
- 회전 ±90°, 가변 FPS, 프레임·시간·좌표 정합성, 오디오 유지, 파일 변경 검출을 실제 FFmpeg로 검사했다. FFmpeg 9와 Debian FFmpeg 5.1의 자동 회전 옵션 차이를 수정하고 양쪽에서 회전 영상을 확인했다.

사용한 얼굴 사진은 [scikit-image의 astronaut 자료](https://scikit-image.org/docs/0.21.x/api/skimage.data.html#skimage.data.astronaut)이며 NASA의 공개 사진이다. 원본 다운로드 주소·해시는 `data/test-assets/astronaut-source.json`에 보존했다. 원본 영상과 얼굴 썸네일은 외부 LLM에 전송하지 않는다.

### 실행 이력·실패 복구

- 누락·중복 트랙, 알 수 없는 트랙·근거 ID, 빈 검색, 누락 사실을 자동 정상 출력으로 처리하지 않는다. 검토 필요 상태는 모든 검출 트랙을 사용자가 지정해야 렌더할 수 있다. 얼굴 0개는 별도 확인이 필요하다.
- 렌더 재전달과 superseded 시도의 늦은 결과가 현재 실행·산출물을 덮어쓰지 않는다. 시도별 경로와 snapshot을 구분한다.
- worker는 **solo / concurrency 1**과 데이터 디렉터리 독점 잠금을 시작 시점에 확인한다. 잘못된 pool, 중복 worker, 저장소 초기화 실패는 작업을 소비하기 전에 종료한다.
- snapshot 파일 쓰기만 실패하고 SQLite가 정상인 경우에도 FAILED 상태와 생성된 관측·근거·판단을 DB에 남긴다. 존재하지 않는 snapshot 링크를 기록하지 않는다.
- SQLite 동시 갱신은 revision 검사로 손실 업데이트를 방지한다. 장시간 영상 처리·외부 호출 중에는 DB 트랜잭션을 유지하지 않는다.
- 저장소를 다시 열고 새 색인을 추가한 뒤에도 기존 실행의 보고서를 재검색·모델 호출 없이 생성했다.

## 재현성·재사용성·응집도·결합도

- Python `uv.lock`, 프런트엔드 `package-lock.json`, Python minor 버전, YuNet 원본 commit·checksum을 고정했다. Docker의 Python·Node base image도 digest로 지정했다. OS의 FFmpeg 버전은 실제 분석·렌더 기록에 남긴다.
- 실행·색인에 설정, 모델 ID, 문서/파일 해시, 코드 fingerprint·패키지 버전·lock hash를 저장한다. 완전한 LLM 재호출 결정성 대신 당시 실제 입력·출력을 보존한다.
- `domain`과 `application`은 FastAPI/Celery/LangChain/OpenCV 객체를 직접 다루지 않는다. 외부 구현은 port를 구현하고 `bootstrap`에서 조립한다. API·UI·CLI·평가는 같은 서비스 흐름을 사용한다.
- 추출·검색·판단·분석·렌더·보고서의 책임을 분리했다. 보고서 생성 시 검색하지 않으며, 처리 수정 시 판단하지 않는다.
- FastAPI 의존성 주입과 LangChain 청킹·Chroma·구조화 출력 연결은 Context7에서 공식 문서를 확인하며 구현했다.

## 검증 환경과 산출물

네이티브: macOS 15.7.9 / Apple Silicon / Python 3.12.15 / Node 24.11.1 / uv 0.12.22 / FFmpeg 9.0.2 / Redis 8.10.2.

컨테이너: Linux ARM64 / Python 3.12 / Debian Bookworm / FFmpeg 5.1.9 / Redis 8. AMD64 Linux 서버와 NVIDIA GPU 하드웨어는 이번 환경에서 실행하지 않았다. CUDA는 초기 구현 범위에 포함하지 않는다.

이번 작업의 로컬 QA 기록은 다음 위치에 있다. `data/`는 Git에서 제외되므로 새 checkout에서는 같은 검사로 다시 생성한다.

- `data/qa/live-workflow-1e7085c6e4e742af94ee4b30a40617e3.png`: 실제 처리 수정 완료 화면.
- `data/qa/live-workflow-1e7085c6e4e742af94ee4b30a40617e3.json`: 브라우저 검증 요약과 원 실행·수정 실행 ID.
- `data/qa/docker-yunet-revision.json`: Linux 실제 검출·처리 수정 검증 요약.
- `data/docker-qa-result.json`: Linux Haar 출력·실패 분석 재시도·이전 시도 보존 확인.
- `data/qa/evaluation/`: 평가 CLI의 합성 사례와 명시적 얼굴 0개 출력 검증 결과.

실행 방법은 [README](../README.md), 팀 공유 계획과 도식은 [PrivFrame_구현계획.md](PrivFrame_구현계획.md)에 있다.

## 아직 측정하지 않은 항목

실제 OpenAI 임베딩·판단 호출, 법적 판단 정확도, 실제 평가 데이터셋에서의 얼굴 검출 recall·재식별 위험은 미검증이다. API 키를 설정하면 `baseline`으로 실호출을 실행할 수 있다. fixture는 자동 대체 수단이 아니며 UI·보고서에 테스트용 실행으로 명시한다.

OCR, 번호판, 인물 재식별, 자동 법령 갱신, 규칙 엔진, CUDA는 계획대로 후속 교체·확장 대상이다.
