# 보호 요건(Requirement)을 1급 객체로 두고 모든 비식별 결정을 요건·근거에 연결한다

기존 코드는 인물 트랙마다 KEEP/BLUR/MOSAIC/MASK 액션 하나를 내고 근거는 문자열로만 붙였다. 그러면 "근거가 결정을 바꿨는가"를 추적할 수 없고 감사자가 "요건이 충족됐는가"를 검증할 대상이 없다. 그래서 법률 분석의 산출물을 쟁점 목록이 아니라 근거(Evidence)가 붙은 요건(Requirement)으로 정하고, 계획자는 요건을 결정(Decision: 대상·범위·형태·강도·구간)으로 바꾸며, 모든 비-KEEP 결정은 요건에, 모든 KEEP 결정은 분석에 연결돼야 검증기를 통과하게 했다.

## Considered Options
- 액션 + 근거 문자열(기존): 추적·검증 불가.
- 쟁점 ID → 액션 매핑 테이블: 규칙 엔진과 같아져 새 쟁점에 대응하지 못함(ADR-0004).
- 요건 객체(채택): 분석 → 요건 → 결정 → 감사 발견의 연쇄가 데이터로 남는다.

## Consequences
- Planner·Auditor·Report의 계약이 모두 요건을 기준으로 정의된다. 베이스라인 계획자 4종도 같은 계약을 내야 비교가 된다.
- 반사실 코퍼스 실험(근거를 바꾸면 결정이 바뀌는가)이 이 연쇄 위에서 측정된다.
