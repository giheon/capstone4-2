### Caveats and UNVERIFIED items

- **YOLO26 exists** (docs: "released January 2026"; paper arXiv 2606.03748, 02 Jun 2026) [7][8]. Changes: optional one-to-one NMS-free head (default one-to-many head still uses NMS), DFL removed, Progressive Loss, STAL, MuSGD. Note the CPU numbers: YOLO26n/s are faster than YOLO11n/s, but **YOLO26m CPU ONNX (220.0 ms) is slower than YOLO11m (183.2 ms)** in Ultralytics' own tables [1][7]. The "43% faster" headline is a throughput figure; 56.1→38.9 ms is a ~31% latency cut (https://github.com/orgs/ultralytics/discussions/23927). Ultralytics' docs list no YOLO13; YOLO27 is "not released" (https://docs.ultralytics.com/models/).
- **Ultralytics CPU test hardware is inconsistently documented**: README says EC2 P4d + ONNX export; the paper says "Intel Xeon CPU @ 2.00 GHz"; ORT version/threads are not stated [2][8]. Treat the ms values as relative only.
- **AGPL covers everything Ultralytics ships** (code, pretrained and self-trained weights; training from scratch does not escape it) [3][4]. YOLO12 and YOLOv13 are also AGPL-3.0 [11][12]. Ultralytics' own `rtdetr-l/x.pt` (53.0/54.8 AP, 114/74 FPS T4; no CPU numbers; https://docs.ultralytics.com/models/rtdetr/) fall under the same AGPL repo.
- **RT-DETRv3** is PaddlePaddle-only (`.pdparams`); numbers are identical to RT-DETR/v2 at inference because the dense-supervision branch is training-only [17]. **RT-DETRv4** was released 2025-11-18 (github.com/RT-DETRs/RT-DETRv4) — not evaluated here [13].
- **DEIMv2 is non-commercial** by its own LICENSE.md (code and weights); its S–X models also sit on Meta's custom DINOv3 License [24][26]. HF cards carry no license tag. Latency hardware is UNVERIFIED (not stated in README v2026-10-22 or arXiv abstract; predecessors used T4 TRT FP16).
- **D-FINE Objects365 caveat** is official: README (2026-08-19) says Obj365-trained checkpoints should not be assumed commercially cleared [18]. DEIM's Obj365 DEIM-D-FINE-X likely inherits the same concern — UNVERIFIED (no statement in [21]).
- **RF-DETR**: README Nano = 48.4 AP vs paper 48.0 (newer checkpoint) [27][31]. Pretraining = Objects365 (seg heads via SAM2 pseudo-labels) + DINOv2 backbone [31]. No GFLOPs published. Legacy `RFDETRBase` is deprecated ("use RFDETRSmall", https://rfdetr.roboflow.com/latest/faq/). Its M3 Pro CoreML numbers (20–74 ms for Nano@384) are the only official Apple-Silicon figures for any DETR here [30].
- **mmdetection is effectively unmaintained**: last release v3.3.0 2024-01-05 [35]; last commit on `main` 2024-02-05 (https://github.com/open-mmlab/mmdetection/commits/main). RTMDet numbers are RTX3090/T4 TRT 8.4 era; no ONNX-CPU numbers; RTMDet-Ins absent from mmdeploy's mmdet support table [32][34].
- **CPU/Apple-Si latency for RT-DETRv2, D-FINE, DEIM, DEIMv2, RTMDet: no official numbers found** (checked READMEs, arXiv abstracts, HF cards). You will need to benchmark ONNX Runtime CPU on your M-series Mac yourself; DETR-family ONNX graphs use `grid_sample`/deformable attention (RT-DETRv2 offers "dsp" discrete-sampling variants for older runtimes [14]).
- **CoreML**: official only for Ultralytics and RF-DETR. For D-FINE/DEIM/RT-DETR, CoreML is community/coremltools-from-ONNX — UNVERIFIED, not documented in their repos.
- **Objects365 coverage for your targets** (from Ultralytics `Objects365.yaml`, 365 classes): has *Person, Handbag/Satchel, Backpack, Luggage, Briefcase, Wallet/Purse, Monitor/TV, Laptop, Tablet, Cell Phone, Book, Notepaper, Blackboard/Whiteboard, Mask, Glasses, Hat, Helmet*; **no "License plate", "Name tag", "Face" or "Head" class** (https://raw.githubusercontent.com/ultralytics/ultralytics/main/ultralytics/cfg/datasets/Objects365.yaml). Objects365-pretrained weights exist for RT-DETR v1 (HF `PekingU/rtdetr_r50vd_coco_o365`, 55.3 AP, apache-2.0; https://huggingface.co/PekingU/rtdetr_r50vd_coco_o365), D-FINE (`_obj365`/`_obj2coco`), DEIM-D-FINE-X, RF-DETR (all variants). None listed for YOLO11/26, RT-DETRv2/v3, DEIMv2, RTMDet (UNVERIFIED beyond their READMEs/docs).
- **HF transformers version** in which RT-DETRv2 / D-FINE were added: UNVERIFIED (docs checked at transformers v5.22.1 [15][19]).
- Activity: RT-DETR last commit 2026-10-09; D-FINE 2026-08-19; DEIM 2026-03-24; DEIMv2 news 2026-10-22; RF-DETR 1.11.2 2026-10-04; ultralytics 8.4.202 2026-11-03; mmdetection 2024-02-05.

**Practical read for PrivFrame (Apache/MIT-preferred, CPU-first):** the permissively licensed candidates with official ONNX export are RT-DETRv2 (S: 48.1 AP, 20 M), D-FINE (N/S: 42.8/48.5 AP, 4/10 M), DEIM-D-FINE (N/S: 43.0/49.0 AP, same cost), RF-DETR Nano/Small (48.4/53.0 AP, ~30 M, but pip + CoreML + Objects365-pretrained), and RTMDet-tiny/s (older, unmaintained). YOLO11/26 have the only documented CPU ms numbers but are AGPL end-to-end; DEIMv2 is the strongest small model (S: 50.9 AP at 9.7 M) but non-commercial.
