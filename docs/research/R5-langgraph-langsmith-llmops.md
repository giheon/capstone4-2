### 1.3 `langgraph dev` / Studio requirements

- Install `pip install -U "langgraph-cli[inmem]"` ("Python >= 3.11 is required"); `langgraph dev` serves `http://127.0.0.1:2024`, Studio at `https://smith.langchain.com/studio/?baseUrl=http://127.0.0.1:2024`; **Studio requires `LANGSMITH_API_KEY`**; set `LANGSMITH_TRACING=false` to avoid sending traces; `--tunnel` for Safari. ([studio](https://docs.langchain.com/oss/python/langgraph/studio))
- `langgraph.json`: `dependencies` (e.g. `["."]`), `graphs` (`"./pkg/file.py:variable"` = `CompiledStateGraph`, or a factory `make_graph(config: RunnableConfig)`), `env`, `python_version` (3.11/3.12/3.13, default 3.11), `store`, `checkpointer`, `http`, `auth`, `image_distro`, `base_image`, `dockerfile_lines`. ([cli](https://docs.langchain.com/langsmith/cli), [application-structure](https://docs.langchain.com/langsmith/application-structure))
- **Custom checkpointers**: a checkpointer passed to `compile()` is ignored by `langgraph dev` — maintainer: "`langgraph dev` is strictly for development and so it is by design that langgraph api will use an in-memory checkpointer" ([issue 5790](https://github.com/langchain-ai/langgraph/issues/5790)). The server provides a built-in Postgres checkpointer in deployment; the alpha escape hatch is `"checkpointer": {"path": "./src/agent/checkpointer.py:generate_checkpointer"}` pointing at an async context manager that yields a `BaseCheckpointSaver` (docs example uses `AsyncSqliteSaver`), "may experience breaking changes in minor version updates"; validate with `langgraph-checkpoint-conformance` and confirm in `langgraph dev --no-browser` logs. ([custom-checkpointer](https://docs.langchain.com/langsmith/custom-checkpointer))

## 3. LangSmith evaluation

**`evaluate` signature** ([reference](https://reference.langchain.com/python/langsmith/evaluation/_runner/evaluate)):

```python
evaluate(target, /, data=None, evaluators=None, summary_evaluators=None, metadata=None,
         experiment_prefix=None, description=None, max_concurrency=0, num_repetitions=1,
         client=None, blocking=True, experiment=None, upload_results=True,
         disable_evaluator_tracing=False, error_handling='log', **kwargs)
```
`target` = `(inputs: dict) -> dict`, a `Runnable`, an existing experiment, or a 2-tuple of experiments (pairwise). `data` = dataset name/UUID, list, or generator of examples. `aevaluate` has an "identical interface" and is required when any node is async. `metadata` reserved keys `models`, `prompts`, `tools` populate experiment-table columns. `max_concurrency` default changed to 0 (no concurrency) in 0.2.0. ([evaluate-llm-application](https://docs.langchain.com/langsmith/evaluate-llm-application), [evaluate-graph](https://docs.langchain.com/langsmith/evaluate-graph))

| Capability | Facts | Source |
|---|---|---|

## 6. Recommendation for PrivFrame

**6.1 LangSmith layout (project-based workspace; stay on Developer/Plus, US or EU endpoint)**

| Object | Naming | Why |
|---|---|---|
| Tracing projects | `privframe-dev`, `privframe-harness`, `privframe-prod` (set `LANGSMITH_PROJECT` per process; Celery worker and API share the value) | Mirrors the four fixed environments LangSmith uses for agent-based workspaces, so a later migration is a rename ([agent-environments](https://docs.langchain.com/langsmith/agent-environments)) |
| Run metadata (every invoke) | `config_hash`, `pipeline_version`, `execution_id` (= thread_id), `models.{node}`, `prompts.{node}` (commit hash), `retriever`, `dataset_version`; tags `node:<name>`, `env:<x>`; plus `LANGSMITH_REVISION_ID` = git SHA | Filterable via `eq(metadata_key,…)`; `revision_id` is auto-stored ([add-metadata-tags](https://docs.langchain.com/langsmith/add-metadata-tags)) |
| Datasets | `pf-e2e` (video → expected redaction set), one per node: `pf-detect`, `pf-legal-rag` (query → gold passages + answer), `pf-decide` (entity + context → mask/keep), `pf-render-qa`; splits `smoke` (≤10), `regression`, `hard`; tag versions `prod` | Node datasets let you evaluate `app.nodes["x"]` directly and keep judge cost low ([evaluate-graph](https://docs.langchain.com/langsmith/evaluate-graph)) |
| Evaluator sets | detect: code evaluators (precision/recall/F1 on boxes/entities); RAG: `RAG_RETRIEVAL_RELEVANCE_PROMPT`, `RAG_GROUNDEDNESS_PROMPT`, `HALLUCINATION_PROMPT` (pass `context`), Korean-language judge `system=`; decide: `exact_match` + `CORRECTNESS_PROMPT`; e2e: trajectory `create_trajectory_match_evaluator("unordered")` + a summary evaluator for leak rate | [openevals](https://github.com/langchain-ai/openevals), [agentevals](https://github.com/langchain-ai/agentevals) |
| Experiments | `experiment_prefix=f"{node}-{config_hash[:8]}"`, `metadata={"config_hash":…, "models": {...}, "prompts": {...}, "dataset_version": "prod@<ts>"}`, `num_repetitions=3` for LLM-judged nodes | Reserved `models/prompts/tools` keys become table columns ([evaluate-llm-application](https://docs.langchain.com/langsmith/evaluate-llm-application)) |

**6.2 Reproducibility**: config = frozen dataclass → `config_hash = sha256(json)`; pin models by exact name + `temperature=0`/seed in `Runtime` context (not state); pull prompts by commit hash (`name:<hash>`) at run start and record the hash in metadata; evaluate on `list_examples(as_of="prod")`; cache judge/LLM HTTP calls in CI with `LANGSMITH_TEST_CACHE`; keep `data/checkpoints.sqlite3` per experiment so time-travel replays are deterministic.

**6.3 Regression gating in CI**: pytest + `@pytest.mark.langsmith` on the `smoke` split with `LANGSMITH_EXPERIMENT_METADATA` set from the config hash; assert absolute thresholds (e.g. leak-rate = 0, groundedness ≥ 0.8) so failures break the build, and nightly `aevaluate` on `regression` with a pairwise `evaluate((baseline, candidate), randomize_order=True)` whose summary you post as a PR comment; mark the winner as the "source experiment" in the UI compare view. Add one online rule on `privframe-prod` sampling 10% to `pf-review` annotation queue (default dataset `pf-e2e`) so reviewed production cases flow back into datasets.

**6.4 LangGraph features to adopt**

| Feature | Verdict |
|---|---|
| `CachePolicy` vs your fingerprint cache | Keep your fingerprint cache for cross-process/experiment reuse (it survives restarts and is keyed on your semantic fingerprint); add `CachePolicy(key_func=<same fingerprint>)` only for in-process deterministic nodes (OCR/detect) so Studio/`langgraph dev` runs also hit it. Only `InMemoryCache` is documented. |
| Durability | `durability="sync"` for the harness and anything with `interrupt()` gates (guarantees the step-0 checkpoint exists before the first node); `"async"` (default) for throughput in prod. |
| `RetryPolicy` / `timeout` / `error_handler` per node | Adopt now for the external model + retriever nodes; note that interrupts bypass retry. |
| `Runtime[Context]` | Move model/prompt/retriever selection out of state into `context_schema` so experiment configs never pollute checkpoints and `config_hash` is derivable from `runtime.context`. |
| `Store` for case memory | Use `InMemoryStore` locally and `PostgresStore` with `index` for cross-video legal-precedent memory; keep per-execution facts in checkpoints. |
| Time travel for re-experiments | Use `get_state_history` + `update_state`/`invoke(None, snapshot.config)` to fork from the checkpoint before a node and re-run it under a new context; this is what your "fork of runs" should wrap. |
| Strict resume | When you upgrade to 1.2.20, consider enabling `__pregel_strict_resume` in the harness to catch stale resumes early (private key, so wrap it). |
| Subgraphs | Compile per-node subgraphs with `checkpointer=None` (per-invocation) so interrupts still bubble up; avoid `True` where you fan out with `Send`. |
| Node evaluation | Expose `graph.nodes[name]` targets in a small eval module that builds `example_to_state` adapters per node. |

**6.5 Splitting service vs harness later**: keep one graph package with a `make_graph(config)` factory (also the `langgraph.json` form), two entrypoints (FastAPI/Celery service, harness CLI), and two LangSmith projects; the diagnostic environment gets `durability="sync"`, caching, repetitions and judges, while the service runs the pinned `config_hash` with online rules only.
